Query sites: the SNPs sampled in the --pile per-SNP pileup CSVs (template analyses/s02-indels/results/vrf-pileup/vrf-pileup-{C}-{D}.csv);
             their per-iteration 'recovered' flags come from that file.
Neighbours : OTHER true hom-div (GT 1|1) variants within +/-200 bp of the query SNP p,
             from the truth VCF (template data/s02-indels/sim/30X/19/{D}/0.005/42/mm39-truth.norm.vcf.gz). A record is a SNP when REF and ALT are
             both 1 bp, otherwise an indel.
Recovered  : per-iteration recovered VCF (template data/s02-indels/iter/{C}/30X/19/{D}/0.005/42/iter{k}/mm39_recovered.acc.vcf.gz), i.e. the variants
             already baked into the consensus at that iteration.
Unrecovered: a neighbour truth variant whose position is NOT in the recovered set
             (set membership, so false-positive recovered calls cannot lower the count).
All coordinates are reference coordinates.

One row per (caller, divergence, query SNP, iteration).

Fields:
  caller                 : variant caller (gatk | bcftools | freebayes)
  divergence             : simulated hom-div divergence D
  snp_pos                : 1-based reference position of the query SNP p
  iteration              : mapping iteration (1 = single-shot)
  n_neighbor_truth       : neighbour true hom-div SNPs in [p-W, p+W], excluding p
  n_unrecovered          : of those, NOT yet recovered at this iteration
  n_neighbor_truth_indel : neighbour true hom-div indels in the window
  n_unrecovered_indel    : of those, NOT yet recovered at this iteration. Indel
                           recovery is by POSITION match of the normalized truth vs
                           recovered indels, so it slightly understates recovery.

WHAT THIS IS
------------
Per divergent-SNP, per-iteration measure of the local "assemblable neighbourhood": how many nearby
truth variants are STILL UNRECOVERED (not yet called into the consensus) around each divergent SNP.
The premise (see the tool docstring): gatk's reference-anchored reassembler fails while the local
sequence is too divergent from the (consensus) reference; as iteration bakes neighbouring variants
into the consensus, the local unrecovered load falls and the site becomes callable.

The *_indel columns mirror the SNP columns so the notebook can contrast the neighbour SNP-vs-indel
unrecovered load across iterations (synthesis §5 "Indels").

KEY READING (s02, pooled fraction still unrecovered = sum(unrec)/sum(neighbor_truth))
------------------------------------------------------------------------------------
At every caller and divergence the indel unrecovered-fraction sits ABOVE the SNP one: iteration
clears indels LESS completely than SNPs, leaving a larger residual (~20-47% of neighbour indels vs
3-30% of SNPs still unrecovered by iteration 3). Strongly caller-dependent: bcftools recovers almost
no indels single-shot (~95% unrecovered at iter 1) then iteration rescues it sharply; freebayes stays
stuck (~47%); gatk improves modestly. Iteration reduces the indel load but cannot eliminate it — that
residual is the divergence it cannot bake into the consensus.
